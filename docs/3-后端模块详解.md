# 后端模块详解

## 一、API 路由模块

### 1.1 路由注册总览

在 `exit.py:init_config()` 中注册所有路由：

```python
app.include_router(userInfo)      # /user/*
app.include_router(socketApi)     # /ws/*
app.include_router(sukinOs)       # /sukinos/*
app.include_router(locationSystem) # /system/*
```

**关键实现细节**:
- **登录** (`login_for_access_token`): 支持 `account`（账号密码）和 `code`（验证码）两种模式。验证码登录时如果账号不存在，自动注册新账号。
- **密码修改** (`update_user_password`): 需要验证码校验 → 密码哈希 → 签发新 Token → 删除旧验证码缓存。
- **Token 刷新** (`refresh_access_token`): 使用 Refresh Token 签发新 Token 对，支持"记住我"状态继承。

#### 1.3.5 APP 管理 (`Api/Location/sukinosAppManage.py`)

| 路由 | 方法 | 说明 | 认证 |
|---|---|---|---|
| `/system/sukinos/appList` | GET | APP 列表（管理端） | superuser |
| `/system/sukinos/statistics` | GET | APP 统计数据 | superuser |
| `/system/sukinos/updateStatus` | POST | 审核/上架/下架 APP | superuser |
| `/system/sukinos/forceUpdate` | POST | 标记/取消当前版本强制更新（仅 active，先校验包可用） | superuser |
| `/system/sukinos/resubmit` | POST | 审核端改包重提，写入待审版本（系统包只读） | root |
| `/system/sukinos/detail/{id}` | GET | APP 详情 | superuser |
| `/system/sukinos/delete/{id}` | POST | 强制删除 APP | superuser |
| `/system/sukinos/appList/withPermission` | GET | APP 列表（附带权限信息） | superuser |
| `/system/sukinos/download/{resourceId}` | GET | 取回当前包或指定 `revisionId` 的原始内联包（attachment） | superuser |
| `/system/sukinos/versions/{resourceId}` | GET | 当前可用版本 + 全部历史/待审版本 | superuser |
| `/system/sukinos/versions/{resourceId}/{revisionId}` | GET | 单个历史版本详情（含 metaInfo） | superuser |
| `/system/sukinos/versions/{resourceId}/approve` | POST | 通过待审版本并切换上线 | superuser |
| `/system/sukinos/versions/{resourceId}/reject` | POST | 驳回待审版本（线上不动） | superuser |
| `/system/sukinos/versions/{resourceId}/activate` | POST | 激活/回滚到未删除历史版本 | superuser |
| `/system/sukinos/versions/{resourceId}/delete` | POST | 逻辑删除历史版本，可选同时清除物理包 | superuser |
| `/system/sukinos/versions/{resourceId}/restore` | POST | 恢复已逻辑删除且物理包仍在的版本 | superuser |
| `/system/sukinos/versions/{resourceId}/meta` | POST | 改元数据：有 pending 改 pending，否则生成待审版本 | superuser |
| `/system/sukinos/files` | GET | 磁盘包文件列表与引用分类（current/live/deletedOnly/orphan） | superuser |
| `/system/sukinos/files/purge` | POST | 批量清理无引用或仅被已删除版本引用的物理包 | superuser |

当前可用版本只存在 `sukinos_app` 单行，非当前版本全部落在 `sukinos_app_revision`（含 `is_pending` 待审暂存）。
同一时间只允许一个待审版本：开发者重复提交会替换自己来源的待审包，审核端需显式 `replaceExisting`。
新版本先进入待审、审核通过后才切换，线上版本始终可用；版本号由服务端在当前行与全部历史（含已删除）里取最大值末段 +1。
历史删除默认只做逻辑删除，物理回收仅限 root：删除时勾选 `purgeFile`，或在文件治理里清理 `deletedOnly`/`orphan` 文件；
仍被当前版本或未删除历史引用的文件会被拒绝清理。

**包完整性**：落盘后计算 worker 包体 SHA-256，并对 `resourceId\nversion\ncontentHash` 做 Ed25519 签名；
环境变量 `SUKIN_APP_SIGN_PRIVATE_KEY` / `SUKIN_APP_SIGN_KEY_ID` / `SUKIN_APP_SIGN_REQUIRED` 控制签名，
开启必签时签名失败按 500 处理。`checkUpdates` 投影下发 `contentHash/signature/signKeyId/signAlg`。

**强制更新**：`force_update` 只允许对 `active` 应用开启，开启前 `verify_current_package()` 校验当前包；
回滚到更低版本时服务端自动置 1，客户端即使本地版本更高也接受这次降级更新。

**修订保留**：系统配置 `sukinos_app_revision_retention`（`maxRevisions`，1–200，默认 20）控制历史修订上限，
重提后剪枝最旧的超额修订及其无引用物理包；当前包本体始终保留。

**系统包只读**：`is_reserved_system_resource()` 拦截 `sys-*` 保留资源的改包、强更与删除，必须走内部发布签名通道。

`download` 只认 `@RequireRoot()`，能取到任意人的私有包——这与静态直链
`Middleware/staticAuth.py` 的「owner + 权限注册池」两套语义是有意分开的（后台审计能力）。
物理文件名一律从库里取并经 `basename`，接口不接受客户端传名；解析成源文件树不在后端做，
由前端 `workerFiles.js` 完成（见 `docs/module/04-process-kernel.md` 4.1）。

### 1.4 SukinOS APP 模块 (`Api/SukinOS/`)

| 路由 | 方法 | 说明 | 认证 |
|---|---|---|---|
| `/sukinos/app/upload` | POST | 上传 APP | 需要登录 |
| `/sukinos/app/update` | POST | 更新 APP | 需要登录 |
| `/sukinos/app/appList` | GET | 公开 APP 列表 | 需要登录 |
| `/sukinos/app/appList/authorized` | GET | 用户有权限的 APP 列表 | 需要登录 |
| `/sukinos/app/checkUpdates` | POST | 检查 APP 更新 | 需要登录 |
| `/sukinos/app/searchApp` | GET | 搜索 APP | 需要登录 |
| `/sukinos/app/myUpload` | GET | 我的上传记录 | 需要登录 |
| `/sukinos/app/delete` | POST | 删除自己的 APP | 需要登录 |
| `/sukinos/localdev/*` | - | 本地开发同步 | 需要登录 |

**上传流程**:
1. 检查文件大小（上限读后端内存态 `upload_quota_cache`，来源是系统配置 `sukinos_upload_settings`，回落链为 指定用户 > 角色 > 全局默认 > `APP_FILE_MAX_SIZE` 兜底值），超限时提示里会报出档位与该档上限
2. 检查磁盘空间（保留 2GB 安全阈值）
3. 生成安全文件名（APP名_版本号_防重复编码）
4. 使用存储抽象层保存文件（目前本地磁盘）
5. 写入数据库，状态为 `under_review`
6. 管理员审核后变为 `active` 或 `disabled`

**更新与版本**:
- `update` 只接受 JS 包，服务端重新解析并清洗包体；已有任意历史修订时拒绝走原地更新，必须先提交待审版本
- 新版本一律写入 `sukinos_app_revision` 并标记 `is_pending`，审核通过后才替换当前行；线上版本在审核期间保持可用
- 同一时间一个应用只允许一个待审版本：开发者重复提交只替换自己来源的待审包，其他情况返回 409
- 版本号由服务端发号（当前行与全部历史含已删除版本取最大，末段 +1），包内旧版本号会被重写
- `checkUpdates` 需要登录并按可见性过滤：本人应用、公开应用或注册池内已授权应用；返回投影含 `forced`，回滚降级后的应用会被标记强制同步

## 二、中间件层

### 2.1 RoutePermissionMiddleware

**文件**: `Middleware/routePermission.py`

全局路由权限检查的核心实现。详见[系统架构](./2-系统架构.md)的中间件详解部分。

**白名单配置结构**:
```json
{
  "publicPaths": [],
  "publicPrefixes": ["/static", "/resource", "/user/status/"],
  "selfPrefixes": ["/system/permission/"]
}
```

### 2.2 StaticAuthMiddleware

**文件**: `Middleware/staticAuth.py`

使用**处理器映射模式**支持多个静态资源挂载点：

```python
AUTH_HANDLERS = {
    APP_FILE_MOUNT: handle_sukinos_app_auth,    # "/resource/sukinos/app/download"
    RESOURCE_USER_MOUNT_PATH: handle_public_auth,  # "/media/user"
}
```

APP 文件放行按状态收紧：非 `active` 包只对 root / 所有者开放；私有包必须带身份并命中所有者或
注册池授权；公开包也需上架后才能匿名下载。系统管理端 `GET /system/sukinos/download/{id}`
走 `@RequireRoot()`，可审计地取任意用户的包，与静态直链语义有意分离。

### 2.3 RequestLogMiddleware

**文件**: `Middleware/requestLog.py`

纯 ASGI 实现，避免 `BaseHTTPMiddleware` 的 `TaskGroup` 并发错误。

**日志过滤配置**:
```json
{
  "rules": [
    {"method": "GET", "path": "/system/status", "enabled": false}
  ],
  "logRequestBody": true,
  "logResponseBody": true
}
```
